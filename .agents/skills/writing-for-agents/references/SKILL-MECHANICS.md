# 技能入口与路由机制

用 `name` 提供稳定的调用标识，用 `description` 界定什么请求应进入该技能。写完后拿两条相邻请求试读（例如「写 PR 正文」与「改 README 语气」），确认读者能准确选到各自对应的入口。

编写前先了解目标仓库与宿主的加载方式：

- 需要模型按请求自动发现的入口，`description` 应列出彼此独立的典型触发场景；仅由用户手动点名的入口，用一句话讲清何时值得调用即可。
- 是否拆分成独立可发现的新技能，取决于它是否有单独出现的请求或明确调用方。多个手动入口若共用同一份说明，可直接指向安装后均能访问的参考文件。

在 cstack 中，`disable-model-invocation: true` 表示手动入口，`meta` 声明子代理或外部技能依赖；仅影响某条分支的说明放进该技能的 `references/`，在分支入口用显式相对链接指明何时阅读；跨技能协作在源码中使用 Obsidian 双链，编译后转为精确技能名。为其他仓库编写指令时，沿用那个仓库实际支持的元数据格式与引用方式。

路由技能要明确自身职责边界：`cobe-help` 面向询问用法的用户，负责只读选型并给出提示词示例；`cobe-mode` 面向明确交付任务的用户，负责匹配并读取目标技能后推进执行。`description` 的自动可见性与显式路由主动读文件是两套不同机制，不可混为一谈。
