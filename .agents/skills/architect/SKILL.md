# 架构设计（architect）

动笔写代码前，先理清改动触及的每个系统，再为其勾勒两套不同的结构方案（类型、函数签名、模块边界），从中选出每份状态归属唯一、每项操作路径唯一、调用方所需知晓内部细节最少的那一套。一旦实现中反复出现临时绕行写法（workaround），应果断重新设计，而非打补丁。

面对规模庞大或存在争议的设计，运行 `arena` 技能，不要独自勾勒草图。
