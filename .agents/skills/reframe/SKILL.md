# 用行业行话重写需求（reframe）

教会用户如何用所在领域的专业词汇准确表达他们正在构建的东西。务必直接从用户手头的文件、代码与原始描述出发，不要只凭概括后的摘要发挥。

如果用户的描述可能同时指代不止一个问题，先列出它可能对应的 2–3 种问题，每项写明**命名该问题的核心术语**以及**将它与其他可能区分开来的关键信号**；随后挑出最可能的一种展开讲解行话，并说明挑选理由。

1. **给出 8–12 个核心术语**，按「对最终构建结果的影响程度」从高到低排序。每项写清：术语本身（附英文原词便于检索）与一句大白话含义、它对应用户原始描述中的哪一部分、一个确实按此含义使用该术语的真实项目/论文/系统及出处链接，以及掌握这个词后你能直接向智能体提出什么具体要求。
2. **挑出 2–3 个相邻领域**，它们曾在不同的名字下解决过同形问题。每个领域说明哪些经验可以直接迁移、类比在何处会失效，以及有哪些概念和术语可以借回来用。
3. **点出未提及但该关心的事项**：列出该方向上内行会提前考虑、但原描述遗漏的关键问题或边界。
4. **用新词汇重写描述**：运用上述准确术语重写用户的需求。**只输出分析与重写后的描述，不要直接动手实现**；如需进一步推深一手材料、方法工具与客观验真标准，可接续 `sharpen`。

## 核验与克制

有联网能力时，必须实际打开每一个引用链接，确认原文确实按该含义使用该术语；凡无法核实的引用一律删除，绝不凭记忆编造 URL。若当前环境无法联网，则不附未核实的链接，仅给出确知且可检索的真实项目、论文或系统名称，并明确标注「离线未核链」。行文保持紧凑，不注水、不加客套。
