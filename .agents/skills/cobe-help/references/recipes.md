# 常用提示词范例库

以下范例按通用 `/<skill-name>` 形式书写（在 `pi` 中可写为 `/skill:<skill-name>`，在 `codex` 中可写为 `$<skill-name>`）；替换尖括号 `<...>` 内的具体对象即可直接使用。

## 理解代码、访谈与上下文交接

- `/in-your-own-words <粘贴冗长杂乱的需求或 Issue 讨论>`
- `/reframe <用大白话描述你想做但叫不出专业术语的东西>`（先学行话并重写需求，常接 `/sharpen` 继续推深）
- `/grill-me 我们打算给归档订单增加恢复入口，先和我分轮厘清谁有权恢复、编号冲突如何处理，再决定是否动手。`
- `/sharpen <准备发送的复杂任务提示词草稿>`
- `先用 /how 摸清 <子系统或目录> 的运行机制，再用 /why 查明 <某处设计或历史改动> 当初为什么要这样写。`
- `/teach 结合运行机制和历史背景，用通俗语言给我讲透 <模块名>，重点对比为什么没采用 <备选做法>。`
- `/recall 回顾我最近 7 天在 <主题或模块> 上的工作进展，并核对当前分支与 PR 状态。`
- `/ketchup`（在长对话或后台任务跑完后，同步自上一条消息以来的进展与待拍板事项）
- `/handoff 下一会话只负责验证导出回归，把已跑的检查、关键产物路径和第一步写成交接单。`
- `/bro`（把上一条满是术语的回复翻译成通俗人话）

## 设计、原型、诊断与编码

- **一键路由修缺陷**：`/cobe-mode 排查并修复 <故障现象>。先在真实路径稳定复现并定位根因，具备本地测试条件时按失败测试先行修复，最后贴出复现前后的真实输出。`
- **疑难故障定位**：`/diagnosing-bugs 切换筛选条件后导出偶尔多出一行，先帮我找到稳定的复现条件与根因，不要急着改代码。`
- **原型验证分歧**：`/prototype 报销单撤回后还能再次送审吗？做一个我能亲自点击体验的状态演示。`
- **跨模块架构选型**：`/architect 我们需要实现 <新功能或重构目标>，先梳理受影响模块并给出两套结构方案对比，等我确认后再写代码。`
- **冻结技术规格**：`/to-spec 把刚才访谈拍板的规则、接口边界与不碰范围冻结为 spec.md，落盘到 <目标目录或上游文档同级目录>。`
- **拆解垂直切片**：`/to-tickets 读取 <spec.md 路径> 并核对当前代码，拆出 3–6 个可独立验证的垂直切片写入同级 tickets/，先停下让我审阅。`
- **干净上下文执行单片**：`/run-ticket 执行 <tickets/01-xxx.md 路径>，严格遵守不碰范围，跑通验收标准后提交讲清原因的原子 commit 并回写状态。`
- **多方案竞赛融合**：`/arena 针对 <复杂设计或棘手重构> 并行探索多套候选方案，盲审选出最佳底座并嫁接其余方案的亮点。`
- **测试驱动开发**：`/tdd 为 <模块> 新增 <行为>，先写出因预期原因失败的测试，再实现最小代码使其通过。`
- **零行为变更重构**：`/cobe-mode 将 <旧模块> 重构收敛到目标结构，保持外部行为完全不变。先写表征测试锁定当前行为，清理死代码后再迁移并证明重构前后输出一致。`
- **性能优化与核验**：`/cobe-mode <操作> 在 <数据集> 上耗时 <数值>。先做性能剖析找出真实瓶颈，优化后严格按 benchmark-checklist 核验并给出对比数据。`

## 审查、影响面与验收

- **评审当前改动**：`/code-review 对照这轮最终确认的需求审查工作区，指出遗漏、多余写入及受影响的调用方。`
- **评估存量架构**：`/architecture-review 列表页与导出任务都在各自计算结算价，查清两者的契约，比较维持现状与收拢规则的成本。`
- **对抗性找真 Bug**：`/interrogate 对当前分支做压力评审，设法写出复现把改动跑挂，只报告主会话重跑证实的真实缺陷，不要改业务代码。`
- **排查外部连带破坏**：`/blast-radius 评估当前 diff 在改动范围之外还可能破坏哪些调用方或隐式契约，找出支撑安全性的核心事实并写脚本跑代码证实。`
- **清理冗余注释与异味**：`/no-comments 检查当前分支相对于 main 的改动，清理冗余注释与违规抑制标记，并在范围内理顺让人费解的局部结构。`
- **多目录分片并行盘点**：`/swarm 并行检查 <目录> 下的各个子包是否满足 <检查条件>，每个子包分配一个工作节点，最后汇总成一张 PASS/ISSUES/BLOCKED 表。`
- **生成与维护项目验证技能**：
  - 初次建立：`/create-verification-skill 为当前仓库生成本地验证技能与功能地图，并实跑跑通一个核心功能。`
  - 后续巡检：`/maintain-verification-skill 巡检当前项目的验证技能与功能地图，核对最新源码并真实运行验收。`

## 大型长任务、写作与沉淀

- **大型非标任务编排**：`/figure-it-out 我们需要将 <旧体系> 迁移到 <新体系>，先设计分阶段可审计工作流、完成谓词与基线脚手架，等我确认蓝图后再进入实验循环。`
- **跨模型外派协同**：`/dispatch 先把 <模块> 的改造规格、文件围栏和验收命令写清楚，派给主力外部模型实现；回来后你亲自审 diff、重跑测试，再用简洁人话向我汇报。`
- **审阅长任务决策轨迹**：`/show-me-your-work 审计本次运行的决策日志与会话记录，并给出需要重点关注的 Attention 风险项。`
- **起草 PR 正文**：`/pr 按仓库模板为当前 diff 起草 PR 正文，清晰交代行为变化、已跑验证与回滚影响。`
- **技术文档写作**：`/technical-writing 为 <模块> 编写一份操作指南（或审阅当前 README / RFC），消除公文腔与模糊指代。`
- **中文内容去 AI 腔**：`/unslop 打磨这篇中文稿件，清除所有 AI 套话并执行四层质检。`
- **编写 Agent 执行指令**：`/writing-for-agents 这份 AGENTS.md 每次改文案都触发数据库校验，帮我收紧读取条件并补齐完成标准。`
- **复盘与根治错误**：
  - 沉淀经验：`/reflect 复盘本次会话中踩过的坑和有效判断，看看有哪些半年后仍成立的经验值得补进现有技能。`
  - 结构化防呆：`/correct 智能体在当前仓库反复出现 <某类错误>，按架构 > 类型/Lint > 测试 > 文档的优先级设计根治方案。`
  - 更新个人模式：`/automate-me 挖掘近期当前工作区的会话记录，增量更新我的 cobe-mode 技能。`
