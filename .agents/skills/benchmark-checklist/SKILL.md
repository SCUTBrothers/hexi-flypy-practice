# 基准测试核验清单（benchmark-checklist）

只要你要产出性能数据（无论是改动前后对比、性能回退声明、持续优化的评测脚手架，还是三方库与配置选型），都必须对照本清单逐项核验。用实际运行产出的证据回答每一个问题，不要靠读代码臆测。

如果用户只是想要一个快速粗略估算（ballpark），跑一次就够了，但依然必须核对第 4 题和第 7 题，并明确注明“仅运行 1 次”；除非那次运行结果明显异常，否则其余问题可以跳过。注意：**在多个备选方案之间做技术选型，绝不能按粗略估算敷衍对待。**

## 开始运行前

- 先用准备写进交付报告的原话把预期主张写下来（例如“在 6 万行数据集上，导出的 p50 耗时降低了 30%”）。下面所有问题都是用来检验这句话的。
- 通读测量脚本，看清它具体对哪段计时、统计了什么、又忽略了什么。
- 用 `uptime` 检查系统平均负载，用 `nproc`（macOS 下可用 `sysctl -n hw.ncpu`）查看 CPU 核心数。若机器负载偏高，查明是什么进程在占资源；若无法停掉干扰进程，将对比双方交替穿插运行以承受同等背景噪点，并在报告中如实说明。

## 七项核验问题

1. **为什么没能再快一倍？（瓶颈在哪？）** 指明当前的瓶颈限制因素（limiter）。在正式计入报告的运行之外单独跑一次性能剖析（profile），因为剖析器和追踪器本身会拖慢运行速度。结合单进程 CPU 占用（`top`、`pidstat`）、运行时剖析器（`node --cpu-prof`、`py-spy`、`perf`）、I/O 等待与系统调用统计（Linux 下 `strace -c`），将热点定位到具体源码行。同时盯紧负载生成器：若施压端自己先打满，测到的其实是施压端上限。若改动没让数字变化，先查明瓶颈再下结论。
2. **双方都调优到位了吗？** 参与对比的每一方都必须按生产环境的真实形态运行：Release 构建、生产参数与环境变量、批处理与事务设置、连接池、与生产一致的冷/热缓存状态，以及相同依赖版本与数据集。若其中一方顶着默认配置跑，比较的其实是配置而非实现。凡属配置层面的瓶颈（逐行提交事务、Debug 构建、漏建索引）都说明该侧未调优；先调优重测再分胜负，无法调优则不得据此选出赢家。
3. **数据有没有突破物理或算术上限？** 动手算账：比对每秒字节数与磁盘/网络带宽、每秒操作数乘单次开销与核心数、节省时间与被改模块原本占用的总耗时。哪怕把占总耗时 10% 的环节删成零耗时，整体最多也只能快约 11%。超出理论上限的结果，测到的必是缓存、空操作（no-op）或提前报错退出的 bug。
4. **运行过程中报错了吗？** 统计失败次数与非成功响应，核验输出内容是否正确而非仅“有返回值”。直接拒绝请求通常极快，超时重试则极慢。若测量脚本未统计错误数，先补上错误计数。
5. **结果可稳定复现吗？** 对比双方至少各跑 5 次，采用交替顺序（A、B、A、B……），使预热、惰性初始化、缓存和机器漂移不偏袒任何一侧。报告中位数与波动范围；小于运行间自然波动的差距属于“无可测量的差异”。差距接近时使用秩和检验或评测工具自带的统计检验。
6. **放到全局有实际意义吗？** 在报告微观基准（micro-benchmark）的同时，用真实数据规模与并发度测量用户真正等待的端到端路径，并交代微观耗时占整体的比例。只占请求 1% 的辅助函数就算优化到零耗时，整体请求最多也只快 1%。
7. **目标工作真的执行了吗？** 确认被测工作确实在计时区间内完整发生：请求到达了服务端、数据落了盘、字节被读取，且代码消费了返回结果。无人迭代的生成器、未 `await` 的 Promise、被 JIT 消除的死结果以及静默超时，都会跑出根本没干活的假数字。

## 报告规范

- **结论先行**：直接给出定性结论——变快、变慢、无可测量的差异，或结论存疑（inconclusive）。
- **报全核心指标**：给出带单位的数值、运行次数、波动范围及瓶颈因素（如“p50 从 41 ms 降至 33 ms，双方各 7 次取中位数，优化后范围 32–35 ms，受限于单核 JSON 解析”）。
- **诚实标记存疑结论**：声称有差异却说不出瓶颈、任一侧未调优到位，或未核验第 4、7 题时，一律判为“存疑（inconclusive）”并点明缺失项。
- **精简 PR 正文**：PR 正文只放一个核心主指标，多次运行明细、范围与剖析证据放入关联文档或产物文件。

## 与性能工作的衔接

- 排查单点性能问题时，在基于基线制定计划前先用本清单核验基线，并对后续每次测量照此核验。
- 进行持续爬坡优化（hillclimb）时，在冻结评测脚手架前先用本清单核验该脚手架，并让脚手架固定打印错误数与实际完成工作量，使每轮保留或回滚自动覆盖第 4、7 题。
