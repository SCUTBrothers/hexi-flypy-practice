# 执行单个垂直切片（run-ticket）

在干净上下文中接手一个 `status: todo` 的垂直切片任务单，严格按边界完成实现与实证验收，产出独立可回滚的原子提交并同步切片状态。

## 1. 读取现场与前置门禁

- **定位目标与上下文**：
  - 默认本地模式：读取目标切片文件（`0k-*.md`），同时自动读取关联的 `spec.md`（优先按切片 frontmatter 显式指向的路径读取，否则读取上级或同级 `spec.md`）与 `depends_on` 指向的前置切片文件（如仅传入目录，选取编号最靠前且所有 `depends_on` 均为 `done` 的 `todo` 切片并在动手前说明）。
  - 外部载体模式：若项目 `AGENTS.md`、注入规则或用户消息指定了外部载体（例如 GitHub Issue `#123`），按该约定读取对应工单与 Spec。
- **核对依赖完成度**：任一 `depends_on` 切片未处于 `done` 状态时，立即停下报告未完成的前置项，不跳过依赖强行开工。
- **核对代码硬冲突**：快速检查切片涉及的源码位置。若发现 `spec.md` 或切片假设与仓库实际代码存在无法直接兼容的硬冲突，停下指出具体文件和矛盾点并给出取舍建议，待用户拍板后再改代码。
- **开干前复述边界**：用 2–4 行交代本片目标、`不碰范围（Out of Scope）` 与计划运行的验收命令；本地模式下同步将该切片标为 `status: in-progress`。

## 2. 范围纪律与实现

- **严守边界**：只改本切片范围内的代码，不顺手重构无关模块，也不提前实现后续切片。
- **衔接工程纪律**：具备低成本本地测试路径时，按 `tdd` 先写失败测试再实现；涉及跨模块边界调整时遵循 `architect`。
- **遇阻塞诚实止损**：遇到外部接口未就绪、环境权限缺失等无法自行解决的阻塞时，将切片标为 `status: blocked` 并在正文写明具体阻塞点后停下，不编造假数据或假通过掩盖问题。

## 3. 实证验收

- 遵循 `principle-prove-it-works`，逐条实际运行切片 `验收标准（Verification）` 中的全部检查、测试或交互核验步骤，留存真实命令与输出。
- 任一必检项未通过前，不得将切片标为 `done`。收尾前可按改动风险对照 `code-review` 快速核对本片 diff 是否有越界写入或漏项。

## 4. 原子提交与状态回写

- **提交授权边界**：
  - 若当前会话已获得用户明确授权提交（例如用户指示“完成后提交”或“一直跑到提交”），仅暂存本片业务代码改动并创建 1 个讲清 **Why** 的原子 Commit；严禁将外部规划目录或不应入库的临时文件混入业务仓提交。
  - 若未获得自动提交授权，完成实现与全部实证验收后停下，展示改动摘要、实测输出与建议的 commit message，待用户确认后再执行提交。
- **回写切片状态**：
  - 本地模式：取得真实 commit 短哈希后，更新目标切片文件 frontmatter 为 `status: done` 与 `commit: "<short-sha>"`（若尚未提交，则保持 `in-progress` 并说明待提交后回填）。
  - 外部载体模式（如 GitHub Issues）：按项目 `AGENTS.md` 或用户约定记录 commit、在 PR 中声明 `Closes #<id>` 或留评收口；未经明确授权不执行推送、创建或合并 PR。

## 5. 收尾交接

汇报本片改动摘要、逐条验收标准的实测结果、commit 锚点，以及下一个满足依赖条件的 `todo` 切片。提醒用户审阅本片 diff 后清空或新开干净会话推进下一片；若本片偏离预期，可利用上一个已完成切片记录的 `commit` 锚点回退后修订切片重跑。
