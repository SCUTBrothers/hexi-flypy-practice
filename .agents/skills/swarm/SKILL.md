# 并行工作组（swarm）

## 启动准备

启动任何子任务前，先建立待办清单，每个阶段列为一项：

1. 界定任务与分片（Frame）
2. 并行分发（Fan out）
3. 核验汇总（Aggregate）
4. 输出报告（Report）

## A 阶段：界定任务与分片（Frame）

1. 明确完成判定条件（done predicate）以及最终必须汇总返回的产物或报告形态。
2. 选定分发形态：按工作分片切分（partition）、让 N 个工作节点对同一简报开展竞速（race），或两者混合。凡涉及竞速，必须在派生前预先声明选拔规则：`首个通过即采纳（first pass）`、`全量排序（rank all）` 或 `择优录取（best-of）`。
3. 选定工作节点模型：常规分片使用宿主默认子代理模型；若开展跨模型竞速，预先点明每个竞速分支使用的模型。
4. 涉及写入操作时，为每个工作节点分配各自独立的可写输出位置（独立 worktree 或独立输出路径）。若工作节点负责验证或测量特定提交，每份简报必须写明精确的 commit SHA；测量类简报还必须写明测量方法（样本数、单样本定义、执行顺序），并要求工作节点在结果中一并记录这两项。

## B 阶段：并行分发（Fan out）

在同一轮并发派生全部 N 个后台工作子智能体。若工作节点需从非默认分支起步，在简报中指示其先检出目标基准分支。

每份任务简报必须完全自包含：写明总目标、作用范围、所负责的精确分片或竞速分支、验证方式以及报告格式。报告状态统一使用附带实证的 `PASS`、`ISSUES` 或 `BLOCKED`。能够证实存在缺陷的工作节点应报告 `ISSUES` 并列出其能证实的**全部**问题，而非遇到第一个就停。

若某个工作节点掉线未返回，带着其余 N-1 个结果继续推进并如实记录。

## C 阶段：核验汇总（Aggregate）

读取所有工作节点的最终结果。凡未按简报要求记录精确 SHA 与测量方法的结果一律作废，重派该节点一次；第二次仍缺失则记为空缺（gap），**空缺绝不等同于通过**。分片覆盖模式下，每个必选分片都必须有结果；竞速模式下，严格执行预先声明的选拔规则（`first pass`、`rank all` 或 `best-of`）。严禁直接原样粘贴工作节点的原始长输出。

## D 阶段：输出报告（Report）

在主会话返回一份整合后的精炼报告：包含结果汇总表、单行问题摘要、空缺或掉线记录，以及所使用的竞速选拔规则（若有）。
