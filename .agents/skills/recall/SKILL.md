# 重建近期工作上下文（recall）

**在开始或恢复工作前，重建用户近期的工作上下文，交回一份精炼的现状简报，说明当前进展到哪一步以及接下来该做什么。**

保持内容紧凑切题。只读取目标工作线所需的信息，读够即止。

完整上下文分布在两类记录中。本地聊天历史保存了你做过的操作与决策；共享记录保存了围绕同一片代码以其他名义发生的一切：持续上报的故障表现、上线后又被回滚的修复、仍在触发的异常。第二类记录分布在版本控制、工单/Issue、文档以及可用的外部工具中，切勿仅凭本地会话记录拼凑全貌。

不同 Agent 的本地会话路径、JSONL 结构与去噪检索方式见按宿主拆分的参考指南：[pi](./references/pi.md)、[codex](./references/codex.md)。只读取本机实际存在对应会话目录的指南。

1. **先分类再路由**。如果用户已经给出了完整的状态摘要（路径、分支、改动内容），直接使用并跳过挖掘。`recall` 用于动手前从近期多次会话中加载上下文，而非接续单条指定会话或撰写对外汇报。
2. **搜索前锁定范围**。明确时间窗口（默认最近 7 天）、具体主题（若有）与目标工作区（默认当前活动工作区；未经明确要求，绝不读取其他项目的会话记录）。向用户复述锁定的范围，切勿悄悄把“全部”缩水成“最近 N 条”。
3. **并行分发扫描聊天历史**。并行派生子智能体，每个负责检索候选会话语料的一个分片。指示每个子智能体：按对应 `references/<agent>.md` 过滤当前工作区，按文件真实修改时间（`ls -t`）排序而非按 UUID 名称排序；先按主题词筛选，再只读匹配会话的高信号片段；跳过当前会话与明显噪音（子智能体、评测、测试会话）。所有子智能体按统一结构返回，每个会话一段：主题、用户目标、已做决策、未完结线索、踩坑与纠正、关联产物（分支、PR、工单），并标注会话来源与 ID。若候选会话只有一两个，跳过并行分发直接检索。原始会话记录留在子智能体内部，主会话只接收提炼后的发现。
4. **只要主题点明了具体功能、文件、子系统或缺陷，同步扫描共享记录**。针对版本控制、项目文档/案例记录及当前可用的工单或监控工具，按数据源并行派生调查子智能体，查明“目前现状如何、此前试过哪些未奏效的做法、还有什么未解问题”，与聊天历史挖掘并行运行。查无结果本身也是有效发现；不可用的外部工具直接跳过并注明。仅在无具体目标的纯个人活动回顾（如“我这周干了什么”）时跳过此步。
5. **对照实时状态核实**。针对挖掘出的 PR、分支、工作树和工单，用 `git` 与 `gh` 逐一核查最新真实状态。若结论取决于当时实际执行过的工具或报错细节，回查完整会话条目而非仅凭裁剪摘要。
6. **按下方输出约定撰写简报**。按工作线索分组，严格聚焦指定主题。

## 输出约定

按“现状摘要 → 各线索状态 → 现存问题 → 下一步行动”顺序组织，次要细节砍掉或后置。

- **现状摘要（Capsule）。** 最多 5 条要点，概括这项工作是什么及整体进展。
- **工作线索（Threads）。** 每条占一行，行首必须带且仅带一个状态标签：`[merged #N]`、`[open PR #N]`、`[in flight <branch>]`、`[verified, uncommitted]`、`[reverted #N]` 或 `[planned, not started]`。未打标签意味着状态尚未查清。
- **现存问题（Problems）。** 最多 5 条反复出现的问题，包含持续出现的故障症状以及曾上线又被回滚的修复尝试，让下一次尝试从上次失败处接力。
- **下一步行动（Next move）。** 眼下最值得推进的唯一一项具体行动。

不阻塞当前工作的相邻特性或工单一律不写。简报超出一屏时，优先删细节而非删线索。通过 `unslop` 打磨文字，聊天结论标注会话来源与 ID，共享记录标注出处（commit / PR # / 工单 / 文档路径），公开输出前脱敏私有信息。

**回复：** 严格按上述约定输出简报。
