# 从基础结构思考（principle-foundational-thinking）

动手写逻辑前，先把数据形态定准。尽早定义核心类型，梳理所有读写访问模式，选择契合高频主路径的数据结构。对数据结构去重（DRY），而非执着于消除每一行重复代码。

在多个参与者（actor）之间共享状态前，先问一句：如果另一个参与者并发修改它会怎样？只要答案不是“毫无影响”，就必须做隔离。

脚手架优先。先清理死代码，再优先落地一切能让后续各阶段受益的基础工作（CI、测试、公共类型）。每次提交保持小步且职责单一。
