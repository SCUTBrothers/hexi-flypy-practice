# Stop Slop 中文版 — 消除中文 AI 写作痕迹

写中文内容时，消除所有可预测的 AI 写作模式。让输出读起来像一个有见识的人在认真聊一件事，而不是 AI 在输出信息。

## 核心原则

写出来的东西要通过一个测试：读者读完之后，分不清这是 AI 写的还是一个有判断力的人写的。

机构口吻可以保留判断力和专业性，但不牺牲口语化、节奏感和活人感。去掉「我觉得」「我认为」是去掉个人叙事感，不是去掉人味。

## 动笔前的强制核查

每次写作前执行：

1. 产品/公司名称三次确认拼写、定位、官网链接
2. 主题对应的最新事件是否过去 3 天内发生，否则搜索更新的切入点
3. 数据来源分级：一手来源（官方公告、官方文档）> 权威二手（机构报告、知名财经媒体）> 普通转载。关键数字必须有来源

## 禁用标点（全文命中数必须为 0）

| 禁用            | 替代         |
| --------------- | ------------ |
| 冒号「：」      | 用逗号       |
| 破折号「——」    | 用逗号或句号 |
| 双引号「"" ""」 | 用「」或不加 |

参见 [禁用标点规则](./references/banned-punctuation.md)。

## 禁用词（全文搜索必须 0 命中）

以下词组绝对不能出现在输出中：

**废话连接词**：说白了、本质上、换句话说、不可否认

**总结套话**：综上所述、总的来说

**编号过渡**：首先...其次...最后

**AI 信号词**：值得注意的是、不难发现、让我们来看看、接下来让我们

**时代套话**：在当今...的时代、随着技术的不断进步

**空洞归纳**：意味着什么、这意味着

参见 [禁用词完整清单](./references/banned-words.md)。

## 禁用结构

| 禁用                           | 替代                                   |
| ------------------------------ | -------------------------------------- |
| 「判断一/判断二/判断三」编号式 | 自然过渡                               |
| 「第一/第二/第三」编号         | 「一个是...另一个是...」「先...再...」 |
| 大段 bullet point 罗列         | 改散文                                 |
| 大量加粗（超过 10 处）         | 控制在全文 10 处以内                   |
| 不必要的小标题                 | 绝大多数文章从头到尾顺下来             |

参见 [禁用结构模式](./references/banned-structures.md)。

## 禁用内容

- 不编造用户案例（「某团队跟我们聊过」是大忌）
- 不写「比如有一次...」假设性场景
- 空泛工具名必须替换为具体名称

## 必须使用的口语化词组（全文至少 8-10 个不同的）

每篇内容必须自然融入以下词组中的至少 8-10 个：

**转场和过渡**：坦率的讲、说真的、我跟你说、其实吧、怎么说呢、回到 xxx 这块

**表达判断**：值得画出来、说到点子上了、不在一个尺度上、说到底、可以确定的是

**承认和自嘲**：说实话也不确定、还在摸索、踩过坑

**情绪表达**：太离谱了、给人整不会了、这数字看了一会儿

**拉近距离**：很多团队会遇到、大家也都知道

参见 [推荐口语化词组库](./references/recommended-phrases.md)。改写示例见 [改前 / 改后对照](./references/examples.md)。

## 切入角度

不要写「某某公司发生了什么」这种新闻通稿式角度。要写：

- 把多个看似无关的事件放到同一张时间表上看
- 找到行业转折点的隐性信号
- 给读者可执行的判断框架

写「分析型 + 实操型」内容，不写「报道型」内容。

## 写作结构

开头 → 结果或反差数据前置，第一段就让人想往下读
背景 → 简要科普，聊天式，不是教科书
核心展开 → 分几个板块，每个板块有一个明确观点、至少一个具体数据/场景/人物支撑、扣主线的句子
行业大图景 → 放到更大的时间表/格局里看
给读者的判断 → 可执行的判断框架，但不要用编号
收尾 → 回扣开头，闭环干净

## 实操内容的处理

如果内容涉及实操，必须给可以直接复制的东西：

- 命令给完整命令行
- 代码给可运行的代码片段
- prompt 给完整模板，读者换括号里的内容就能用
- 配置给具体参数

包装方式是「场景叙述带出操作」，不是「第一步第二步」的手册体。

## 补充规则

保留原意，并匹配预期语气。以下规则补充词句层面的检查，不放宽前面的禁用词、标点、结构和口语化要求。这里的词表示意不是新增禁词表，出现时检查它是否替代了具体动作、对象、来源或数字。

1. **肤浅的“通过/从而”结构。** “通过……，实现……，从而……”、“在……的同时，提升……”、“不仅……而且……”。删掉空泛目的，补具体动作或真实来源。

2. **含糊归因。** “专家认为”、“业内普遍认为”、“有观点指出”、“数据显示”但不给出处。点名来源，或删除。

3. **AI 高频大词。** 赋能、闭环、抓手、底层逻辑、颗粒度、对齐、拉通、沉淀、落地、路径、生态、势能、护城河、组合拳、顶层设计、认知升级、长期主义、复利、飞轮、北极星、第一性原理、降维打击、方法论、范式、底座、中台、矩阵、链路、场景化、价值锚点、心智、杠杆、编排、治理、反哺、复用。换成具体动作、对象或数字。中英夹杂的 leverage、align、deliver、insight、solution 也算。

4. **花哨的“是/有”。** “作为……的重要载体”、“是……的关键一环”、“扮演着……角色”、“具有……意义”。说“是”、“有”，或直接写作用。

5. **“不仅……而且……”“不只是……更是……”。** 直接说结论。

6. **同义词轮换。** 用户、客户、受众、人群、群体在一段里轮着换。选一个，重复用。

7. **虚假范围。** “从战略到执行”、“从 0 到 1 再到 N”、“从认知到落地”。两端不在同一尺度时，直接列事项。

8. **标题腔。** 中文没有英文 Title Case，不要照搬。标题说清主题，不喊口号，不标题党，不堆书名号。

9. **装饰性 emoji。** 从标题和项目符号里删掉。

10. **谄媚语气。** “好问题”、“你说得对”、“非常棒的问题”。直接回应。

11. **过度模糊。** “可能或许在一定程度上”、“有望”、“或将”、“某种程度上”、“可以说”。删掉不提供信息量的模糊副词或改成明确判断；但必须保留真正反映事实不确定性的措辞，绝不为追求干脆而制造虚假确定感。

12. **泛泛结论。** “未来可期”、“前景广阔”、“相信会越来越好”。给具体计划、数字或条件。

13. **抽象隐喻名词。** 底座、基石、脚手架、接口面、原语、模态、范式、镀金、棘轮、终局、北极星、飞轮、护城河、抓手、闭环、链路、势能、心智、生态位。除非是机制本名，否则选具体词。

14. **说清它做什么，而不是它给人什么感觉。** “让数据触手可及”、“让复杂变简单”、“打造一站式闭环”、“赋能业务增长”、“提升用户心智”都只是在命名感觉。改成机制或数字：“查询接口返回最近 30 天的订单，延迟低于 200 ms”、“列重命名会让构建失败”。如果一句话不能重述成具体指令、事实或数字，删掉。若这句话原样放到另一个项目也成立，它没有说明这个项目。

15. **缩短或拆分密句。** 读者要回头重读，就拆成两句或删从句。一句一个意思。

16. **主动语态。** 抓“被、受到、得到、得以、加以、进行、予以”。能点执行者就点。“查询会被校验”改“编译器校验查询”。被动只在执行者未知或确实不重要时用。

17. **删副词，或换更强的动词。** “显著提升”、“大幅优化”、“有效赋能”、“持续加强”改成数字或具体动作。副词在撑弱动词，说明动词选错了。

18. **优先用朴素词。** “进行、实施、开展、利用、助力、赋能、打造、构建、实现、提升、优化、完善、加强、推进、落实”经常空。改成具体动词。“用”不要“utilize/leverage”，“如果”不要“若……则”堆公文腔。更花哨的同义词很少更清楚。

19. **过度压缩。** 无主句、名词堆叠、箭头、缩写会让读者解码而不是阅读。“解析器拒绝错误日期 → 退出码 2，不写入”改成“解析器拒绝错误日期，以退出码 2 退出，并且不写入任何内容”。写完整句子，把箭头和缩写写出来。

20. **翻译腔。** “进行了一个……的操作”、“对于……而言”、“在……的背景下”、“基于……的视角”、“通过……的方式”、“被认为是”、“之一”。改成中文自然句。不是所有“之一”都错，检查是否空泛。

21. **中英夹杂。** 能用中文就用中文。API、SQL、HTTP 这类术语保留。不要用 leverage、align、deliver、insight、solution、case、review 装专业。

22. **名词堆叠和无主句。** “业务价值闭环链路打通方案”、“用户增长场景化运营矩阵”。拆成谁做什么：“运营把用户增长拆成拉新、留存和召回三张表，每周更新一次。”

## 四层质检（每次写完强制执行）

### L1 硬性规则扫描

逐条搜索全文，统计命中数：

- 冒号「：」命中数
- 破折号「——」命中数
- 双引号「""」命中数
- 禁用词清单命中数
- 编号式结构命中数
- 空泛工具名命中数

全部为 0 才能通过。

### L2 风格一致性

- 开头是否从具体当下事件切入
- 是否有长短句交替
- 是否有至少 3 处一句话独立成段
- 是否使用了至少 8-10 个推荐口语化词组

### L3 内容质量

- 每个核心观点是否都有具体数据/人物/场景支撑
- 知识点是否以「聊着聊着顺手掏出来」方式呈现
- 是否有文化/哲学/历史升维
- 多个案例是否用了升番逻辑（最炸的放最后）

### L4 活人感终审

通读一遍，回答：

- 这是一个有见识的普通人在聊一件被打动的事，还是 AI 在输出信息？
- 是否有体感记忆型表达？
- 是否有独特角度？
- 心流是否顺畅，有没有断点？

### 质检报告输出格式

```
## 质检报告

**L1 硬性规则** ✓/✗
- 冒号：X 处命中
- 破折号：X 处命中
- 双引号：X 处命中
- 禁用词：X 处命中（具体词：...）
- 编号结构：X 处命中
- 空泛工具名：X 处命中

**L2 风格一致性** ✓/✗
**L3 内容质量** ✓/✗
**L4 活人感** ✓/✗

**总评**：X 层通过 / Y 层需要返工
**修复优先级**：[列出最需要修复的 1-3 个具体问题]
```

## 大改之后必须重跑质检

每次结构性修改、新增段落、删除段落之后，重新逐项扫描。不能依赖前一次的结果。
