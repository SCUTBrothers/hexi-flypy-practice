# 跨模型外部调度（dispatch）

本技能用于让当前主控 Agent（负责产品理解、架构规划、前端/UX 与对人沟通）通过本机 CLI 调度**异构外部模型**分担其更擅长的环节，与宿主内置的同家族 subagent 定位互补。具体的 CLI 命令、模型档位与速度参数见 [模型配置与 CLI 命令参考](./references/pi-models.md)。

## 何时派单、何时自己做

面对包含多个环节的复合任务时，**按能力强弱拆单**：只将契合外部模型强项的子任务整理成清晰规格外派，把其余环节留在当前主控会话自行完成。各 Provider 与模型档位的具体强弱项与禁派边界，先查阅 [模型配置与 CLI 命令参考](./references/pi-models.md)。

- **适合派单**：
  - 严谨的后端逻辑、算法、状态机、类型建模或复杂重构实现（主控先定清晰规格，外部模型按规格一次性落地）。
  - 从一串任务中拆出的规则明确、可脚本自测的纯工程子任务。
  - 跨模型第二意见与冷酷代码审查（用另一模型家族打破同源盲区，专抓边界、并发、契约回归与逻辑漏洞）。
  - 棘手 Bug 或性能问题的独立排查与攻坚。
  - 用户明确点名使用某个外部模型协助。
- **不要派单（留在当前主控会话自己做）**：
  - UI 视觉与布局设计、交互体验打磨、产品文案或面向人类的文档润色。
  - 需求尚未收敛的开放式探讨（应先由主控与用户敲定方案，再把可执行部分外派）。
  - 几行能改完的简单改动、单点事实问答或常规闲聊。
  - 当前会话本身已被作为 `dispatch` 外部工作节点调用时，**禁止再次递归派单**。

## 1. 选择档位与执行模式

按任务复杂度从 [模型配置与 CLI 命令参考](./references/pi-models.md) 中挑选模型档位，不把具体模型名写死在任务逻辑里：

- **轻量档**：信息查证、局部小改、快速初审或简单脚本。
- **主力档（默认）**：日常后端/核心逻辑实现、排障与常规代码审查。
- **攻坚档**：复杂架构推导、棘手并发/边界攻坚、深度对抗式审查。

按任务性质决定工具与工作区边界：

- **只读审查 / 咨询模式**：显式收窄内置工具为只读集合（保留已装无害扩展），不落盘持久化会话（`--no-session`）。
- **写入实现 / 返工模式**：
  - **常规小中改动**：直接在当前工作区执行，主控通过 `git status` 与 `git diff` 逐行验收。
  - **大改动、高风险重构或当前工作区已有未提交脏改动**：先切独立分支或建 `git worktree` 隔离，避免外部修改与现有改动纠缠（遵循 `principle-separate-before-serializing-shared-state`）。
  - 为本次派单分配唯一的会话 ID（`--session-dir` + `--session-id`），确保多轮返工精准续接同一上下文且不与并发任务串话；排除交互提问类工具（如 `--exclude-tools ask_question`），防止外部进程半路挂起。

## 2. 撰写可执行 Brief 与防跑偏约束

将派单规格写入临时文件（如 `$TMPDIR/dispatch-<task-id>/spec.md`），以文件方式传入外部 CLI，避免 Shell 转义出错并方便复核。Brief 须包含五项要素：

1. **目标与验收标准**：要达成什么可观察结果，以及必须跑通的精确验证命令。
2. **允许改动的文件围栏**：明确列出可修改的目录或文件范围。
3. **禁止触碰的区域**：明确禁改前端样式、UI 文案、无关代码或未授权的依赖升级。
4. **入口文件指针**：给出最相关的源码路径与关键符号，减少盲搜耗时。
5. **汇报格式要求**：要求对方只输出「改动文件清单 / 实际运行的验证命令与输出 / 遗留风险或假设」，禁止长篇公文与客套。

通过附加系统提示（`--append-system-prompt`）同步约束外部模型：

- 严格按 Brief 一次性自主完成并自跑验证命令，**不要中途停下等待确认**；仅当遇到无法绕过的规格硬矛盾时立即停止并直接汇报矛盾点。
- 严禁越出文件围栏，严禁擅自执行 `git commit`、`git push` 或破坏性操作。

## 3. 主控全责验收与返工闭环

外部模型返回后，主控对最终交付负全责，**绝不原样照搬外部模型的公文输出，也不轻信其口头「已完成」声明**：

1. **只读任务验收**：核对每条发现是否指向真实文件与行号，剔除无依据的风格挑刺或误报；涉及代码缺陷时按需由主控亲自复现核实。
2. **写入任务验收**：
   - 检查 `git status` 与 `git diff`，确认没有越出文件围栏或混入多余改动。
   - 亲自重跑关键测试或验证命令确认真实通过（遵循 `principle-prove-it-works`）。
3. **精准返工与熔断**：若验收发现漏项或边界缺陷，携带具体 diff 位置与报错，用**同一个 `--session-id`** 下达聚焦返工指令；若连续 2–3 轮返工仍跑偏，立即停手改由主控接管或请用户拍板。
4. **对人交付**：由主控整理成简洁、清晰、易读的人话汇报最终变化、实测验证结果与遗留风险；未经用户明确授权，绝不提交或推送。
