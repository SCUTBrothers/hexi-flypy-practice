# 用原型回答一个设计问题（prototype）

先把待决争议收窄为一句能通过演示回答的问题，并置顶展示在原型中。若用户已经敲定方案并要求正式实现，直接进入开发即可，不必多此一举做原型。

## 按问题类型选择分支

- 想验证状态与规则（例如「连续取消、恢复之后哪些操作仍然合法」），阅读 [逻辑与状态原型](./references/LOGIC.md)，交付一个双击即可打开的单文件 HTML。
- 想对比界面与信息布局（例如「把信息放在哪儿能让用户一眼找到」），阅读 [界面原型](./references/UI.md)，在同一路由下提供多种结构迥异的可切换方案。

分支不明确时，先结合问题所属的模块或页面做判断；仍有歧义则请用户澄清。若用户暂时无法答复，选用更贴近当前代码形态的分支，并把前置假设写在演示顶部。

## 原型边界与收尾

- 在目标模块或页面附近明确标注原型范围。默认仅使用内存数据；只有待验证的问题本身涉及持久化时，才使用明确标记的临时数据库或文件。
- 把精力集中在真正回答问题的核心交互上，逐项亲手操作核验，无需为一次性演示外壳额外搭建完整测试套件。
- 交付可直接双击打开的本地文件，或一条项目自有的启动命令与可访问的变体地址。
- 用户体验后，记录待解问题、选定结论与可重跑的原型位置。待用户授权进入正式实现时：逻辑原型只迁入经过验证的纯逻辑，界面原型按正式工程规范实现选定结构，演示外壳、其余变体与切换器均留在原型内。提交到临时分支或更新外部工单须先获得用户授权。
