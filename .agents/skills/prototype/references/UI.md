# 界面原型

围绕用户当前需要拍板的一项具体界面决策展开设计（例如「同一笔订单的待办事项与历史记录应该同屏展示，还是分标签查看」）。

## 复用现有环境

- 优先复用现有页面、组件与数据形态，保留原有的路由参数、鉴权与只读加载逻辑。
- 使用贴近真实场景的数据密度；涉及数据写入的动作一律在原型内部模拟。若暂无合适页面可挂载，按项目惯例新建临时路由并明确标注其原型用途。

## 变体设计与切换体验

- **结构差异优先**：默认提供 3 种结构差异明显的变体，自行决定数量时不超过 5 种；用户已指定数量时按要求提供。沿用项目既有的组件与样式，共享同一份数据与控件，为各方案独立安排信息层级、布局结构或主操作入口。若两套方案仅在配色或文案上有差异，重做其中一套。保持输入数据、视口尺寸与任务目标一致，确保公平对比。
- **可分享的切换机制**：通过同一路由的 `?variant=A` 等查询参数切换方案，同时保留其他既有查询参数，确保链接可直接分享且刷新后仍停留在同一变体。
- **固定切换栏与键盘支持**：共用一个固定在底部的切换栏，显示当前变体代号及方案名称，支持通过前后按钮与键盘左右方向键首尾循环切换。当焦点位于输入框、文本域或可编辑区域时，方向键必须留给光标编辑，不得误触切换。
- **严格隔离生产环境**：用项目的开发模式开关包裹整个原型入口（含所有变体、模拟数据、键盘监听与切换栏），确保生产环境完全不受影响。

## 交付与核验

交付可直接打开的变体地址。交付前逐项核验鼠标点击、方向键循环、输入框内光标移动、页面刷新以及窄屏显示效果。若挂载在既有页面上，还须在生产模式下分别打开原始地址与带 `?variant=` 参数的地址，对照改动前的同一路由逐项核对页面布局、数据展示与操作入口。用户体验后既可选定某一套方案，也可指明要组合的局部元素；记录最终决定与遗留取舍。若待推演的是状态转换规则，改读 [逻辑与状态原型](./LOGIC.md)。
