# 逻辑与状态原型

在页面顶部醒目写出待回答的问题与一条可证伪的预期（例如「两名编辑者先后撤销时，最终能恢复哪一版？」）。输入项、操作按钮和状态名称一律沿用业务术语，便于熟悉业务的人直接核对。

## 实现方式

- 将 HTML、CSS 与 JavaScript 内联到单个本地 HTML 文件中，离线双击即可打开。
- 按问题特点选用纯 reducer、显式状态机或一组纯数据转换函数；若领域模型本身带有持续状态，也可用方法清晰的对象封装。
- 让 DOM 交互层调用独立的逻辑模块，保证核心逻辑能够脱离页面单独运行。

## 交互与演练设计

- **完整状态面板**：用带业务标签的字段展示全部相关状态，每次操作后实时刷新。
- **自由操作区**：所有动作按钮始终可点击，触发非法操作时同样清晰提示被拒绝的原因。
- **分步演练标签页**：为正常路径、边界情况与非法操作各建一个独立标签页，写明本场景需要观察什么。每次启动演练都先重置回已知初始状态，每一步提供独立的可点击按钮，点击执行真实动作后再进入下一步。

交付前先断网打开该文件，逐一走通自由操作与分步演练，如实记录与预期不符的结果，并将可重跑文件与结论一并交接。若待评估的是界面布局而非状态逻辑，改读 [界面原型](./UI.md)。
